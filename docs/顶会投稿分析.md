## 目前的优势

- 核心 idea 有意义：基于语义的前景/背景感知稀疏化
- 质量保持好，ImageReward 甚至提升
- 三层加速叠加（sparse attn + sparse FFN + step skip）设计合理

## 关键差距

### 1. 实验规模严重不足
- **当前**：20 prompts × 3 seeds = 60 张，1 个模型
- **顶会标准**：5K-30K 张，FID 用 COCO-30K 或 DrawBench/PartiPrompts 等标准 benchmark
- **建议**：用 COCO-30K captions 或 DrawBench (200 prompts) + PartiPrompts (1600 prompts) 做评测

### 2. 缺少与现有方法的对比
这是最致命的问题。审稿人第一反应就是"和 XX 方法比怎么样"。必须对比：
- **DeepCache** (CVPR 2024)：step-level caching，和我们的 full_skip 思路类似
- **FORA** (2024)：attention 缓存加速
- **Delta-DiT** (2024)：残差预测跳步
- **ToMe** (token merging，我们已有实现但没对比)
- **PAB** (Pyramid Attention Broadcast)

### 3. 只测了一个模型
- **当前**：Lumina-Next-T2I（相对小众）
- **顶会标准**：至少 2-3 个主流模型
- **建议**：加 PixArt-α、SD3 或 Flux — 证明方法的通用性

### 4. 缺少理论分析
- 为什么前景每步计算、背景可以缓存？需要从扩散过程的角度分析
- 可以做：不同步数 fg/bg 的 noise_pred 变化幅度分析，证明 bg 变化确实小

### 5. 缺少系统的消融实验
需要清晰的 ablation table：
- 只有 sparse attn → +sparse FFN → +step skip 的逐层提升
- 不同 skip_ratio 的影响
- 不同 mask 方法的对比（已有 cfg_magnitude/complexity/semantic）
- sparse_start_step 的影响

## 具体行动建议（按优先级）

1. **补对比实验**：实现 DeepCache 作为 baseline（最重要的竞争对手，思路也是 step-level caching）
2. **扩大评测**：用 PartiPrompts 1600 条 + COCO-5K，跑标准 FID/CLIP Score
3. **加第二个模型**：PixArt-α 是 DiT 架构，代码迁移成本最低
4. **写清楚 story**：不是"我们加速了 2x"，而是"扩散生成中前景/背景的语义不对称性可以被利用"——这是一个 insight-driven 的工作
5. **补消融表格**：把已有的各种实验整理成系统的 ablation

## 方法三层架构总结

```
Step 0-5:   Dense（建立 mask + 基础图像结构）
Step 6-29:  三层加速叠加
  ├── Layer 1: Sparse Attention（attn1 只对前景 token 做 SDPA）
  ├── Layer 2: Sparse FFN（背景 token 复用上一步 FFN 缓存）
  └── Layer 3: Full Step Skip（每 3 步跳过整个 transformer，外推 noise_pred）
```

- bg refresh 间隔 = 5（每 5 步做一次 dense refresh 更新 bg）
- full skip 间隔 = 3（每 3 步完全跳过 transformer）
- 前景每步都通过 transformer 计算（sparse 模式下 attn1 + FFN 只处理前景 token）
